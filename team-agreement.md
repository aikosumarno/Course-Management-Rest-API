# Team Working Agreement

## Communication

**How will you communicate?**  
- Texting

**Response time expectations**  
- Within 24 hours, same day when possible

**Immediate vs. asynchronous communication**
- **Immediate communication:**
  - Time conflicts (can’t make it to meetings)
  - Merge conflicts
  - Assigning work
  - Approaching deadlines
- **Asynchronous communication:**
  - Individual work
  - Progress updates
  - Pushing code

---

## Meetings

**Meeting format**  
- Both in person and remote, as needed

**Meeting frequency (outside weekly TA meeting)**  
- Fridays, 2–3 PM

**Meeting length**  
- Around 1 hour

**Scheduling meetings**  
- Coordinated through text

**Missing or rescheduling meetings**  
- Notify the other member at least 24 hours beforehand and reschedule if needed

---

## Contribution and Workload Expectations

**Target grade**  
- A

**If teammates want different target grades**  
- Discuss and find a midpoint

**Unequal workload scenarios**  
- Acceptable if one team member is busy or unwell for a milestone and the other is willing to take on more work  
- For the following milestone, the workload should be compensated by the other member

**Factors affecting availability**
- Course loads  
- Work

**Reduced capacity periods**
- Midterm-heavy weeks: Feb 23 – March 13

**Definition of equal contribution**
- Completing tasks in a timely manner  
- Splitting tasks evenly based on complexity and time required

**Work redistribution during busy weeks**
- Normally split 50/50  
- If one member is busy: ⅓ / ⅔ split based on availability  
- If both are busy: still split 50/50

---

## Implementation and Workflow

**Task tracking**
- Shared document

**Communicating deadlines**
- Texting and in-person/online meetings

**If a deadline cannot be met**
- Communicate with partner to coordinate a plan to meet the assignment deadline

**Indicating work completion**
- Progress updates via text  
- Demos during meetings

**Linting**
- Enabled with extensions  
- No default rules disabled

**Pushing changes**
- After each work session

**Code review turnaround**
- Within 24 hours of pull request submission

**Pull request size**
- One feature per pull request

---

## Optional Clarifications

**Code consistency**
- Read and understand each other’s code before making changes  
- Communicate drastic changes in advance and use detailed commit messages

**Resolving implementation disagreements**
- Explain reasoning and reach a mutual agreement
